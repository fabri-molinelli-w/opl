# CU-01 · Autenticación y gestión de usuarios con roles — Plan

> Plan aprobado. Orden obligatorio: contrato → migración/queries → generate → service → handler → UI → verificación.

## Alcance
- Servicios tocados: **backend** (Go) y **frontend** (React). `ai-service` no participa.
- Punto de control: (1) contrato + backend → `make generate` + `make verify` → detenerse; (2) frontend → `make verify` + `make check-generated`.

## Reglas transversales
- `/api/health` sigue público.
- Control de roles **centralizado** por `operationID` (oapi-codegen strict pasa el operationID a cada `StrictMiddlewareFunc`), con **default-deny** y allowlist pública (`getHealth`, `login`).
- RN-3: usuario desactivado rechazado aunque el token siga vigente (verificar `active` en cada request).
- Login: mismo mensaje y tiempo similar para email inexistente y contraseña incorrecta (hash dummy).
- Nunca loguear contraseñas, hashes ni tokens.
- Dependencias backend: solo `github.com/golang-jwt/jwt/v5` y `golang.org/x/crypto/bcrypt`.

## 1. Contrato OpenAPI
Tags `auth`, `users`. Endpoints:
- `POST /api/auth/login` (público, `x-min-role: public`)
- `GET /api/auth/me` (`soporte`)
- `POST /api/auth/me/password` (`soporte`)
- `GET /api/users` (`admin`)
- `POST /api/users` (`admin`)
- `PATCH /api/users/{id}` (`admin`)

Schemas: `User` (sin `password_hash`), `LoginRequest` (password sin minLength → 401 siempre), `LoginResponse`, `CreateUserRequest` (password minLength 8), `UpdateUserRequest` (`minProperties: 1`), `ChangePasswordRequest`.

## 2. Migración
`backend/db/migrations/00002_create_users.sql`: tabla `users` (id uuid, email, name, password_hash, role check, active default true, timestamps) + unique index `users_email_uq ON users (lower(email))`. Sin `deleted_at`.

## 3. Queries sqlc
`backend/db/queries/users.sql`: `CreateUser`, `GetUserByID`, `GetUserByEmail`, `ListUsers`, `CountAdmins`, `UpdateUser` (COALESCE + `sqlc.narg`), `UpdateUserPassword`.

## 4. Backend
- `internal/config/config.go`: `JWT_SECRET` (obligatoria, ≥32 chars), `JWT_TTL` (default 8h), `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
- `internal/domain/{errors.go,user.go}`.
- `internal/auth/{password.go,jwt.go,policy.go,middleware.go}`.
- `internal/service/{auth.go,user.go}` + interfaces de repo locales.
- `internal/repository/user.go` (wrapper sqlc, mapea `pgx.ErrNoRows`→404 y `23505`→409).
- `internal/api/handlers/{errors.go,auth.go,users.go}` + ajuste de `health.go`.
- `cmd/opl/main.go`: wiring + bootstrap admin (RN-4).
- Traducción dominio→HTTP en un único punto (`ResponseErrorHandlerFunc`).

## 5. Frontend
- `src/api/http.ts`: token desde `sessionStorage`; 401 limpia sesión + redirige a `/login`; 403 → "No tenés permisos".
- `src/auth/{AuthContext,RequireAuth,RequireRole}.tsx`.
- `src/features/auth/LoginPage.tsx`, `src/features/account/AccountPage.tsx`, `src/features/users/{UsersPage,UserForm}.tsx`.
- `src/layouts/AppLayout.tsx` y `src/routes.tsx` con menú/guardas por rol.
- Solo hooks/tipos de `src/api/gen/`; prohibido `as any`.

## 6. Tests
Backend: uno por CA (CA-1..CA-5) con fakes + `TestProtectedEndpoints_AuthMatrix` (401 sin token / 403 rol insuficiente para cada endpoint protegido). Frontend: login ok/ko, redirect en 401, menú por rol.
