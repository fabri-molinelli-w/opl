# CU-02 · Inventario de servidores y servicios — Plan

> Plan aprobado. Orden obligatorio: contrato → migración/queries → `make generate` → service → handler → UI → verificación.
> Punto de control original: backend completo + `make generate` + `make verify`; luego frontend + `make seed` + `make verify` + `make check-generated`.

## Alcance
- Servicios tocados: **backend** (Go) y **frontend** (React). `ai-service` no participa.
- Sin dependencias nuevas de runtime. `gopkg.in/yaml.v3` se usa solo en tests para leer el contrato.

## Decisiones aprobadas
1. `policy_contract_test.go` lee `api/openapi.yaml` y compara cada operación con la política. Si la operación tiene `security: []` o `x-min-role: public`, debe ser pública; si no, el rol de `Policy` debe coincidir con `x-min-role`. No se tocan los tests existentes.
2. `servers.ip` es `inet` en base. Se lee con `host(ip)`, se escribe con `$n::inet` y el dominio usa `string`. Validación con `netip.ParseAddr` en el service.
3. Filtro de tags con `tags @> ARRAY[sqlc.narg('tag')::text]::text[]` para aprovechar el índice GIN.
4. `make seed` es manual, idempotente y documentado en el README como solo desarrollo. Sin `APP_ENV`.
5. `serverId` es inmutable: no aparece en `UpdateServiceRequest`.
6. JSON y query params en camelCase, igual que el schema `User` (`createdAt`, `updatedAt`). SQL/DB en snake_case. Se registra en `AGENTS.md`.
7. Tests de integración con `//go:build integration` y target `make test-integration` contra el Postgres de `docker compose`. Cubren CA-4 y RN-6. Fuera del CI.
8. `domain.Error` se extiende con `Details`. Se agrega test de regresión para las respuestas de error existentes.
9. `NewServer` recibe `handlers.Deps` para no cambiar la firma en próximos CU.

## 1. Contrato OpenAPI
Tags nuevos `servers` y `services`.

Paths:
- `GET /api/servers` (`listServers`, soporte) — filtros `q`, `environment`, `os`, `tag`, paginados.
- `POST /api/servers` (`createServer`, sysadmin) — 201, 400, 409.
- `GET /api/servers/{id}` (`getServer`, soporte) — incluye `services`.
- `PATCH /api/servers/{id}` (`updateServer`, sysadmin).
- `DELETE /api/servers/{id}` (`deleteServer`, sysadmin) — 204, baja lógica.
- `GET /api/services` (`listServices`, soporte) — filtros `serverId`, `environment`, `status`, `type`, paginados.
- `POST /api/services` (`createService`, sysadmin).
- `GET /api/services/{id}` (`getService`, soporte).
- `PATCH /api/services/{id}` (`updateService`, sysadmin).
- `DELETE /api/services/{id}` (`deleteService`, sysadmin) — 204.

Schemas: `Location`, `ServiceType`, `CheckType`, `Server`, `CreateServerRequest`, `UpdateServerRequest`, `Service`, `CreateServiceRequest`, `UpdateServiceRequest`, `PaginatedServers`, `PaginatedServices`.

Convención de nombres: `pageSize`, `serverId`, `checkType`, `checkTarget`, `expectedStatus`, `intervalSeconds`, `latencyThresholdMs`, `currentStatus`, `createdAt`, `updatedAt`.

## 2. Migraciones
- `00003_create_servers.sql`: tabla `servers` con `ip inet`, checks de environment/location, `tags text[]`, `deleted_at`, índice único parcial `lower(hostname) WHERE deleted_at IS NULL`, GIN de tags e índices de filtros.
- `00004_create_services.sql`: tabla `services` con FK a `servers`, checks de type/port/check_type/status, defaults y `deleted_at`. Índices por `server_id`, status y type.

## 3. Queries sqlc
- `servers.sql`: `CreateServer`, `GetServerByID`, `ListServers`, `CountServers`, `UpdateServer`, `SoftDeleteServer`.
- `services.sql`: `CreateService`, `GetServiceByID`, `ListServicesByServerID`, `ListServices`, `CountServices`, `UpdateService`, `SoftDeleteService`, `SoftDeleteServicesByServer`.
- Filtros opcionales con `sqlc.narg`, paginación con `sqlc.arg`.
- `ListServers` lee `host(ip) AS ip`; escrituras usan `::inet`.

## 4. Backend
- `internal/domain`: tipos de inventario y `FieldError`/`Details` en `errors.go`.
- `internal/repository`: wrappers sqlc y baja transaccional servidor+servicios con `pgx.Tx` + `Queries.WithTx`.
- `internal/service`: validación de IP, hostname, enums, puerto, URL HTTP, defaults, paginación y conflictos.
- `internal/api/handlers`: `Deps`, conversores y handlers sin lógica ni SQL.
- `internal/auth`: operaciones nuevas en `Policy` y test contrato↔política.
- `cmd/seed`: semilla idempotente de 5 servidores ficticios y sus servicios.

## 5. Frontend
- `InventoryPage`: tabla de servidores, buscador, filtros y paginación en la URL (`q`, `environment`, `os`, `tag`, `page`, `pageSize`).
- `ServerDetailPage`: ficha con servicios.
- `ServerForm` y `ServiceForm`: alta/edición con errores 400/409 junto al campo.
- Acciones de escritura solo para `sysadmin` y `admin`; `soporte` en solo lectura.
- Solo hooks y tipos de Orval; prohibido `as any`.

## 6. Tests
- Backend: unitarios por CA/RN, contrato↔política, regresión de errores y handlers con `httptest`.
- Integración: CA-4, RN-6 y unicidad case-insensitive con `//go:build integration`.
- Frontend: `InventoryPage`, filtros de URL, formularios con errores y ficha de servidor.

## 7. Verificación
```bash
make generate
make verify
make check-generated
# opcional, con Postgres de docker compose:
make test-integration
```
