> Plan aprobado. Orden: contrato → migración/queries → `make generate` → service → handler → UI → verificación.
> Punto de control: backend completo + `make generate` + `make verify`; luego frontend + `make verify` + `make check-generated`.

## Alcance (recortado para la entrega)
- Entra: ABM, búsqueda, filtros por categoría y etiqueta, orden, historial de versiones, bloqueo optimista opcional, Markdown seguro con botón copiar.
- Queda para después: vínculos con servidores/servicios (`document_links`) y `index_status` (se resuelve en CU-09 con reindexación completa).

## Decisiones aprobadas
1. `documents.version int NOT NULL DEFAULT 1`. Cada PATCH exitoso la incrementa.
2. Query params en camelCase (`pageSize`, `sort`, `order`).
3. `sort=title|updatedAt`, `order=asc|desc`, default `updatedAt desc`. El `ORDER BY` **no** se arma concatenando texto: el contrato restringe los valores (enum) y la query sqlc usa `CASE`. Valor inválido → 400.
4. `document_versions` guarda un snapshot completo (título, contenido, categoría, etiquetas, autor). Se inserta la versión 1 al crear y una nueva por cada edición, en la **misma transacción** (RN-4).
5. Bloqueo optimista: el PATCH acepta `version` opcional. Si viene y no coincide con la actual → 409 con `details[].field = "version"`.
6. Título duplicado → 409 con `details[].field = "title"`.
7. `GET /api/documents/{id}/versions` devuelve solo metadatos; el contenido se pide con `GET /api/documents/{id}/versions/{version}`.
8. Búsqueda `q` con `ILIKE` sobre título, contenido y etiquetas; el service escapa `%`, `_` y `\`. Mejora futura: `pg_trgm` / `tsvector` (ADR-020).
9. Dependencias nuevas del frontend: `react-markdown` + `remark-gfm`. Sin `rehype-raw` ni `dangerouslySetInnerHTML`; se mantiene el `urlTransform` por defecto (bloquea `javascript:`).
10. Límites: título 3-150 caracteres, contenido obligatorio de hasta 200 KB, hasta 20 etiquetas de hasta 40 caracteres (se normalizan a minúsculas sin duplicados).

## 1. Contrato
- `GET /api/documents` (`listDocuments`, soporte) — `q`, `category`, `tag`, `sort`, `order`, `page`, `pageSize`.
- `POST /api/documents` (`createDocument`, soporte) — 201, 400, 409.
- `GET /api/documents/tags` (`listDocumentTags`, soporte).
- `GET /api/documents/{id}` (`getDocument`, soporte).
- `PATCH /api/documents/{id}` (`updateDocument`, soporte) — 200, 400, 404, 409.
- `DELETE /api/documents/{id}` (`deleteDocument`, sysadmin) — 204.
- `GET /api/documents/{id}/versions` (`listDocumentVersions`, soporte).
- `GET /api/documents/{id}/versions/{version}` (`getDocumentVersion`, soporte).

## 2. Migración
`00005_create_documents.sql`: `documents` (índice único parcial `lower(title)`, GIN en `tags`) y `document_versions` (único `(document_id, version)`).

## 3. Tests
- Service con fakes: validaciones, normalización de etiquetas, escape de `q`, conflicto de versión, sort por defecto.
- Handlers con `httptest`: CA-3 (409), CA-4 (403 para soporte en DELETE).
- Integración (`//go:build integration`): CA-1 (crear y encontrar), CA-2 (editar genera versión y la anterior se consulta).
- Frontend: listado, vista con bloque de código + botón copiar (CA-5), Markdown sin ejecución de `<script>` ni `javascript:`.
