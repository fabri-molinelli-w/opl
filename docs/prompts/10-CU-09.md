# 10 · CU-09 OPSBot (chatbot con RAG + tools de solo lectura)

- **Fecha:** 2026-10-26
- **Caso de uso / tarea:** CU-09 — chat en panel lateral; RAG sobre la documentación de CU-05 y consulta del inventario de CU-02.
- **Herramienta y modo:** Claude Code (ADR-021) · plan + build con punto de control.
- **Modelo:** Claude Opus (`claude-opus-5-5`)
- **MCP usados:** ninguno en esta sesión.

## Decisiones tomadas en el plan

1. **Proveedor de LLM intercambiable.** `ChatOpenAI` con `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL`: sirve para
   Gemini, Groq, OpenCode Zen u Ollama sin tocar código (se agotaron los créditos de OpenCode Zen).
2. **Sincronización por versión (ADR-023)** en lugar de `/ingest`: el ai-service no recibe escrituras.
3. **fastembed (ADR-022)** en lugar de sentence-transformers: sin PyTorch, instalación liviana para Debian.
4. **Fuentes registradas por las tools**, no generadas por el LLM: CA-1 no depende de que el modelo cite bien.
5. **Memoria por usuario + sesión:** la clave incluye el `X-User-Id` que pone el backend; un usuario no puede
   leer la conversación de otro adivinando un `sessionId`.
6. **Errores sin filtrar detalles internos:** si el ai-service falla, el backend loguea el detalle y responde
   503 `unavailable` con un mensaje genérico.

## Prompt

> Implementá CU-09 con el alcance recortado: tools `buscar_documentacion`, `estado_servicios` y
> `buscar_servidores` (solo GET con el JWT del usuario). El ai-service sincroniza Chroma comparando versiones
> de `GET /api/documents`. Backend: `POST /api/chat` (soporte) que reenvía con `X-Internal-Token`, el JWT y
> `X-User-Id`; 503 si no está configurado o falla. Frontend: panel lateral con sugerencias, Markdown seguro y
> fuentes con link. Tests: solo-GET (CA-4), fuentes (CA-1), sin información (CA-2), token interno, memoria.

## Resultado

- **ai-service:** `app/config.py`, `schemas.py`, `backend_client.py` (solo GET), `rag/{splitter,embeddings,store,sync}.py`,
  `agent/{prompt,tools,memory,agent}.py`, `main.py`; 11 tests (pytest), ruff y mypy --strict en verde.
- **Backend:** contrato `POST /api/chat` (`chatWithOpsbot`, `x-min-role: soporte`), `internal/aiclient`,
  `service/chat.go`, `handlers/chat.go`, token del usuario en el contexto (`auth.WithToken`), error de dominio
  `ErrUnavailable` → 503. Config opcional `AI_SERVICE_URL` / `AI_INTERNAL_TOKEN`.
- **Frontend:** `features/chat/ChatPanel.tsx` (botón OPSBot en el header), con test.
- **Infra:** `make setup-ai`, `make run-ai`, `make verify-ai`; job `ai-service` en el CI.

## Verificación

- Unit tests en los tres servicios + CI.
- Prueba de punta a punta sin internet: un servidor falso compatible con la API de OpenAI que pide una tool
  y luego responde. Recorrió frontend → backend → ai-service → tool → backend (GET con el JWT) → respuesta con
  fuentes, y `POST /chat` sin token interno devolvió 401.
- Pendiente con el LLM real elegido para la demo (lo corre el usuario con su key en `.env`).
