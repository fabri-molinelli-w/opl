# 09 · CU-05 Base de documentación

- **Fecha:** 2026-10-26
- **Caso de uso / tarea:** CU-05 — ABM de documentos Markdown con categorías, etiquetas, búsqueda, orden, historial de versiones y bloqueo optimista.
- **Herramienta y modo:** Claude Code (sesión remota con acceso al repo) · plan revisado + build. Cambio de herramienta registrado en ADR-021.
- **Modelo:** Claude Opus (`claude-opus-5-5`)
- **MCP usados:** ninguno en esta sesión (GitHub vía la integración de la sesión).

## Contexto

Se agotaron los créditos de OpenCode con el plan de CU-05 ya armado. El plan del agente de OpenCode dejó 12
preguntas abiertas ("Riesgos y dudas a resolver antes de Build"). Se respondieron por escrito y quedaron en
`docs/plans/CU-05.md`. La revisión humana agregó dos ajustes de seguridad que el plan no explicitaba:

1. **Orden sin SQL dinámico.** El plan proponía `sort`/`order` pero no decía cómo implementarlo. Armar el
   `ORDER BY` concatenando el parámetro es una inyección SQL clásica. Se exigió: enum en el contrato,
   validación en el service y `CASE` con claves fijas en la query sqlc.
2. **Markdown sin HTML crudo.** `react-markdown` sin `rehype-raw` ni `dangerouslySetInnerHTML`, con el
   `urlTransform` por defecto que neutraliza `javascript:`.

## Prompt

> Decisiones: 1) `documents.version int NOT NULL DEFAULT 1`. 2) camelCase en query params. 3) OK
> `sort=title|updatedAt` y `order=asc|desc` (default `updatedAt desc`); el ORDER BY NO se arma concatenando
> strings: lista blanca en el service y CASE en la query sqlc; valor inválido → 400. 4) [vínculos: pospuestos].
> 5) El snapshot de `document_versions` incluye título, contenido, categoría y etiquetas; todo PATCH
> incrementa la versión. 7) Aprobadas `react-markdown` y `remark-gfm`, sin `rehype-raw`. 8) 409 con
> `code: conflict` + `details[].field` (`title` | `version`). 11) `GET /versions` devuelve solo metadatos.
> Actualizá spec y plan, implementá backend primero y detenete en el punto de control.

## Resultado

- **Contrato:** tag `documents`, 8 operaciones (`listDocuments`, `createDocument`, `listDocumentTags`,
  `getDocument`, `updateDocument`, `deleteDocument`, `listDocumentVersions`, `getDocumentVersion`) con
  `x-min-role` (todo `soporte`, salvo DELETE `sysadmin`). Enums `DocumentCategory`, `DocumentSort`, `SortOrder`.
- **Migración `00005_create_documents.sql`:** `documents` (único parcial `lower(title)`, GIN de etiquetas) y
  `document_versions` (único `(document_id, version)`).
- **Backend:** `domain/document.go`, `service/document.go` (validaciones, normalización de etiquetas, escape de
  comodines, bloqueo optimista dentro de la transacción vía callback), `repository/document.go`
  (`SELECT ... FOR UPDATE` + UPDATE + versión en una transacción), `handlers/documents.go` (quien crea/edita sale
  del JWT), política de roles y `cmd/seed/documents.go` con 6 documentos ficticios.
- **Frontend:** `components/Markdown.tsx` (render seguro + botón Copiar), `features/documents/` con listado
  (buscador, filtros, orden y paginación en la URL), vista con historial navegable y editor con vista previa
  lado a lado. En un 409 por versión, el texto escrito se conserva.
